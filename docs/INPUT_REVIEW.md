# Input and allocation review — October 21–22, 2026

The C ABI is unchanged. PNG, BMP and PNM dimensions and generated resize/transform buffers are checked before pixel allocation. Encoded input, filtered PNG data and individual pixel buffers have a 512 MiB cap; this is not a total-process memory guarantee. DEFLATE now checks before each literal, stored-block and back-reference expansion instead of waiting for a whole block to finish. PNG requires a first/unique IHDR, a valid empty IEND and exactly the declared filtered data length.

These are conservative parsing changes: truncated PNGs missing IEND and oversized or inconsistent streams that previously progressed further are rejected. Existing format exclusions (Adam7, sub-8-bit PNG, compressed BMP) remain. No new codec dependencies were added. Existing registry snapshot/clone semantics remain; multiple image handles and simultaneous transforms can multiply memory use.

Windows 11 Home build 26300 x64: 25 Debug and 25 Release tests passed, with the optional external-Pillow export test intentionally ignored in each suite. Existing pixel-exact Pillow fixtures still pass. Added boundary tests cover extreme dimensions, pre-growth DEFLATE limits, truncations, mutations and a bounded malformed corpus. Strict host/Windows lint/check and Release DLL build passed. A compiled-DLL Python consumer independently generated zlib PNG fixtures, verified every decoded pixel, checked oversized PNG/resize refusal, then independently verified DLL-generated PNG CRCs, zlib data and row filters back to the original pixels.

`tests/native_interop.py` runs in Windows CI without third-party Python dependencies. These are bounded regressions and differential checks, not coverage-guided fuzzing, a sanitizer run or a complete security audit. Native ARM64, aggregate memory exhaustion and broad format conformance remain separate. Release panic strategy is unwind for the existing FFI guard; invalid caller pointers and allocator aborts remain outside that guard.
