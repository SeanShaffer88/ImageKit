# ImageKit

Image decode, transform, and encode behind one clean C ABI — in pure
Rust with **zero dependencies**. DLL #6 in the Windows DLL Collection.

ImageKit reads PNG, BMP, and PNM images into RGBA pixels, transforms
them (resize, crop, rotate, color ops, blur, thumbnails), and writes
PNG or BMP back out. The DEFLATE codec, PNG codec, and BMP codec are
hand-written in this repo, and the decoder is cross-checked
pixel-for-pixel against files produced by Pillow/libpng.

## ABI (`include/imagekit.h`, prefix `ik_`)

Images live behind `uint64_t` handles. Every transform returns a
**new** handle and never mutates its source, so pipelines can branch
and originals survive edits.

| Function | Purpose |
|---|---|
| `ik_load_file(path)` / `ik_load_bytes(data, len)` | Decode (format sniffed: PNG/BMP/PNM) → handle, or 0 on failure. |
| `ik_free_image(handle)` | Release an image. |
| `ik_info(handle)` | `{"width":W,"height":H,"format":"rgba8","source":"png"}` JSON. |
| `ik_width` / `ik_height` / `ik_get_pixel` | Dimensions; pixel as `0xRRGGBBAA`. |
| `ik_resize(h, w, h2, bilinear)` | Nearest-neighbor or bilinear scaling. |
| `ik_thumbnail(h, max_w, max_h)` | Aspect-preserving shrink-to-fit; never enlarges. |
| `ik_crop(h, x, y, w, h2)` | Bounds-checked crop. |
| `ik_rotate(h, 90\|180\|270)`, `ik_flip(h, horizontal)` | Quarter turns and flips. |
| `ik_grayscale`, `ik_invert`, `ik_adjust(h, brightness, contrast_pct)`, `ik_blur(h, radius)` | Color ops + separable box blur. |
| `ik_encode_png` / `ik_encode_bmp` | Encode to a caller-owned buffer (`ik_free_buffer`). |
| `ik_save_png` / `ik_save_bmp` | Encode straight to a file. |
| `ik_version*`, `ik_last_error*`, `ik_free_string` | Version info, thread-local errors, string disposal. |

Errors carry the shared 0–6 codes plus `IK_ERR_CORRUPT` (7) for
invalid image data.

## Formats (v0.1)

- **PNG decode**: color types 0/2/3/4/6, bit depths 8 and 16 (16-bit
  keeps the high byte), all five row filters, palette transparency.
  **Interlaced (Adam7) PNGs are refused** with `IK_ERR_NOT_SUPPORTED`,
  as are sub-8-bit files.
- **PNG encode**: RGBA8, per-row adaptive filter selection (minimum
  absolute-difference heuristic), zlib stream from the in-tree
  fixed-Huffman DEFLATE compressor with LZ77 matching.
- **BMP decode**: uncompressed 8-bit palette / 24-bit / 32-bit,
  top-down and bottom-up. **BMP encode**: 24-bit.
- **PNM decode**: binary P5/P6 at maxval 255.
- Not in v0.1: JPEG (needs a decoder an order of magnitude larger —
  see ROADMAP), GIF, TIFF, WebP.

## Safety posture

Decoders validate before they allocate: chunk CRCs are verified,
declared dimensions are checked against the actual data at every
step, and pixel buffers are capped at 512 MiB so a hostile header
can't force a giant allocation. Distances, palette indices, and crop
rectangles that escape the image are precise errors, not panics.

## Verification

- 18 unit tests: the full transform set against hand-computed pixels,
  the FIPS-style SHA/DEFLATE vectors (round-trips incl. 100 KB
  payloads), PNG/BMP/PNM round-trips, and the FFI lifecycle
  (including that using a freed handle is an error, not a crash —
  a bug the test suite caught during development was a registry
  deadlock on transforms; the registry now clones out from under its
  lock).
- **Interop (the load-bearing tests)**: fixtures generated by Pillow
  (`tools/make_fixtures.py`) — RGB gradient (a dynamic-Huffman
  stream), RGBA alpha ramp, palette quadrants, grayscale — decode
  pixel-exactly; and a PNG written by our encoder was read back by
  Pillow with correct pixels (verified locally; the fixtures keep the
  Pillow→ImageKit direction asserted in CI).
- Gate (WinDevKit `tools/gate.sh`): fmt, clippy on host **and**
  `x86_64-pc-windows-msvc`, full suite — green. The DLL is pure
  logic (no Win32 calls), so the host gate + CI's Windows build cover
  the same code paths.
